# 0045 — Released on crates.io, with one command: `morningstar`

Status: Accepted (2026-11-17). Prepared and checked here: every crate packages, the packages carry no secret, private address or personal path, and a standalone app generated by the command passes its own tests and builds into an APK against the packaged crates (through `[patch.crates-io]`). The preview runs through the command for an app in this repository. **Published** on 2026-11-18: 0.1.0 of all twelve crates (crates.io lets a new account create about one new crate every ten minutes after the first five, so it took an hour), then 0.1.1, which adds only the `repository` link (a published version's metadata cannot be changed). A standalone app's preview, and anything on a device from a standalone app, have not been tried.

Uses [0007](0007-dependency-policy.md) (no new dependency), [0020](0020-app-identity-and-launcher-icons.md) (identity in `Cargo.toml`), [0038](0038-live-rooms.md) (opt-in services), [0040](0040-development-preview.md) (the preview's runner) and [0041](0041-new-app-generator.md) (the generator). Supersedes the part of 0041 that makes every app a member of this workspace: that remains true for `morningstar-new`, and is no longer the only way.

## Context

Until now Morningstar was used only from inside this repository. Every crate said `publish = false`, an app found the framework by a path in the workspace, and the preview, the Android build and the generator were scripts and binaries of the checkout. The owner chose a public release on crates.io so that an app can be started anywhere with `cargo install` and `cargo add`, under MIT OR Apache-2.0.

Two facts shaped the decision:

- The name `morningstar` on crates.io belongs to another project, a 2022 library for solar charge controllers. Every `morningstar-*` name was free (checked on 2026-11-17).
- The Android host (`templates/android`) and the build script are not Rust crates, but an APK cannot be built without them. The host's Java half and the library's JNI half are one interface, so they must come from the same release.

## Decision

### 1. What is published

Twelve crates, one version for all, released together:

| Crate | Is |
| --- | --- |
| `morningstar-framework` | The public API. Its library is named `morningstar`, so app code is unchanged: `use morningstar::ui::prelude::*;` |
| `morningstar-core`, `-gpu`, `-text`, `-layout`, `-runtime`, `-ui`, `-android`, `-ios` | The framework's crates, as before |
| `morningstar-devtools` | Screenshots in tests, `morningstar-diff`, `-icon`, `-svg`, `-new`; a generated app's dev-dependency |
| `morningstar-preview` | The preview (ADR 0040) |
| `morningstar-cli` | The `morningstar` command (section 2) |

The examples, the benchmark and `docs-snippets` stay unpublished (`publish = false` stays the workspace's default; a published crate says `publish = true`).

The workspace's dependencies carry both a path and an exact version (`version = "=0.1.0"`). Cargo uses the path here and keeps only the version in a published manifest. The exact requirement keeps one release together: an app on 0.1.0 can never resolve a `morningstar-android` of 0.1.1 beside a host of 0.1.0.

The framework crates' `tests/` are left out of the packages. They read fonts from the examples, which are not published. The tests are unchanged here and are still run here.

The licence is MIT OR Apache-2.0: `LICENSE-MIT` and `LICENSE-APACHE` at the root, linked into every published crate.

### 2. The command

`morningstar-cli` installs one binary, `morningstar`:

| Command | Does | Built from |
| --- | --- | --- |
| `morningstar new <package>` | A standalone app in `./<package>` (section 3) | `scaffold.rs` (ADR 0041) |
| `morningstar preview` | The app of the current directory in a window | `morningstar-preview` (ADR 0040), with the package found from the current directory |
| `morningstar build android [--abis] [--install]` | What `tools/build-android.sh` does, for an app anywhere | The host carried in the binary |
| `morningstar icon`, `diff`, `svg` | The devtools' commands | `morningstar_devtools::commands` |

To share code without duplicating it, the bodies of `morningstar-icon`, `-diff` and `-svg` moved into the library (`morningstar_devtools::commands`). The binaries are now three-line wrappers, so both routes run the same code.

The Android host travels inside the command. `tools/morningstar-cli/android` is a link to `templates/android`; `cargo package` follows it, and the crate's `include` list takes exactly the host's sources (17 files, never what Gradle builds there). `HOST` in `android.rs` embeds them with `include_bytes!`, and a test holds that list to `git ls-files templates/android`. A file added to the host therefore fails a test until `HOST` and `include` name it too.

`build android` writes the host to `<target>/morningstar/android-host` of the app's workspace. It writes only the files that differ, so Gradle redoes nothing. A host of another release (`.morningstar-release`) is removed whole first. After `cargo ndk` it reads the app's `Cargo.lock` and refuses a `morningstar-android` of another release than its own, naming the command that fixes it. Everything else is the script's logic: icons into the build directory, a clean `jniLibs`, a fresh APK, the app's services passed to Gradle, and `--install` with `adb`.

iOS is not in the command: its build needs Xcode and has never run (ADR 0021).

### 3. A standalone app

`NewApp::standalone(true)` and `create_standalone_app` write the same app as `morningstar-new` from the same templates. Templates now say `@@if workspace` / `@@if standalone`, and their commands come from placeholders. The differences:

- `Cargo.toml` has its own `version`, `edition` and `publish`. It depends on `morningstar = { package = "morningstar-framework", version = "=<release>" }` and has `morningstar-devtools = "=<release>"` as a dev-dependency. It has an empty `[workspace]`, so it is a project of its own wherever it is put, and the root workspace's `[profile.release]` (small and fast for phones).
- The README and the design guide give `morningstar preview`, `morningstar build android`, `morningstar icon` and `morningstar diff`, run in the app's directory.
- A `.gitignore` for `target/` and `out/`.

The release written into it is the generator's own version, which every crate of a release shares.

### 4. The preview of a released command

The preview builds a runner crate that depends on `morningstar-preview` (ADR 0040). From a checkout that dependency is a path. From a release, Cargo's cache holds the sources, and Cargo may clean that cache. So a released preview names itself by version instead (`morningstar-preview = "=<release>"`). It recognises a release by the `Cargo.toml.orig` that `cargo package` writes into every published crate.

### 5. Publishing

The owner publishes. It is public and permanent: a version can be yanked but never deleted. Steps:

```sh
cargo login                       # the owner's crates.io token; never stored in the repository
cargo publish --workspace --dry-run \
    --exclude atlas --exclude barua-talk --exclude callready --exclude docs-snippets \
    --exclude fundidesk --exclude hello-gpu --exclude showcase --exclude services-check \
    --exclude morningstar-bench
cargo publish --workspace (the same --exclude list)
```

`cargo publish --workspace` (Cargo 1.90 and later) publishes in dependency order and waits for each crate to be in the index. A next release changes `version` in `[workspace.package]` and every `=x.y.z` in `[workspace.dependencies]` together.

## Consequences

- An app can live anywhere: `cargo install morningstar-cli`, `morningstar new`, then `cargo test`, `morningstar preview`, `morningstar build android`. Inside this repository nothing changed: `morningstar-new`, `tools/preview.sh` and `tools/build-android.sh` work as before.
- The source is public under MIT OR Apache-2.0 from the first publish.
- A change to `templates/android` reaches users only in the next release of `morningstar-cli`, together with the matching `morningstar-android`.
- `cargo package` warns that each framework crate's tests are not included. That is expected.
- The preview of a standalone app can only be tried once the crates are on crates.io. Before that, its runner cannot resolve `morningstar-framework`.
