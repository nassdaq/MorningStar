Architecture Decision Records

Each record states one decision, why it was made, and what it costs. An accepted record is not edited to change its decision; a new record supersedes it.

0019Effects: HTTP, recording, playback and stored values done by the hosts with the platform's own stacks, asked for as data and answered as messages; an install id and stored values at setup; a test driver in place of a hostAccepted
0020App identity declared once in the app's Cargo.toml ([package.metadata.morningstar]: name, id, icon), read through cargo metadata; launcher icons and names generated per build for both hosts, never checked into the templates; a single icon becomes the Android adaptive icon by one stated ruleAccepted
0021The viewport (size, insets, keyboard, text measurement) as an argument of the view; rows that wrap, inside the four layout sweeps; scrolling asked for through effects, positions kept by identity; a bounded multi-line field as a scroll view of its own text; implicit animation and enter/leave transitions by identity, frames only while something moves; a Navigator that is plain stateAccepted
0022Text measured and placed as a browser does: fractional widths and pen positions (a quarter of a pixel), the browser's baseline rule (half-leading rounded down, each line's top to the nearest pixel row), kerning across spaces, optional ligatures off under letter spacing, no hinting; a dashed border starts where Chrome's doesAccepted
0023Colours composited as sRGB-encoded values, like the web platform (non-sRGB target, colours encoded on the CPU, images and gradients in the same space); light text weighted to Chrome's; no linear-light mode. Supersedes the compositing space of 0002, 0011, 0014, 0015 and 0017Accepted
0025Text selection owned by the framework (word by double tap or long press, two handles, a contextual menu, highlight per line and per bidi run, scrolling under a dragged handle), caret keys and shortcuts as text events, the selection mirrored to and from the input method, the clipboard as a platform service read only on Paste, a bounded undo history; the application still sees only on_input(String)Accepted
0026Light or dark system-bar icons declared per frame (from the theme background's luminance, or Application::system_bars) and told to the host on change; the platform's "reduce motion" setting in FrameInfo, followed by the UI layerAccepted
0027SVG files loaded at run time by a strict reader written here (a static subset: shapes, groups, transforms, clips, gradients, dashes, currentColor; everything else an error with its line and column; bounded for untrusted input), drawn through the vector-picture path and cache; single-ink files as masks in the glyph atlas; SvgAsset to parse a bundled file onceAccepted
0028Group opacity: PushLayer/PopLayer in the display list, drawn into an offscreen target per nesting depth with render passes split at layer boundaries and blended back as one quad; a frame without layers unchanged; in the UI, a layer only where a faded widget overlaps itself, colour by colour otherwise. Supersedes the per-colour opacity of 0021Accepted
0029Text under a transform that turns, slants or scales: glyphs rasterised from their outlines for the transform, with quarter-pixel pen fractions on both axes, and drawn in screen space (PushScreenSpace); while the transform changes from frame to frame the renderer resamples upright glyphs as before and one more frame is asked forAccepted
0030The icon generator flattens transparency on sRGB-encoded values, as the renderer and the launchers composite (0023); resizing stays in linear light. Amends a detail of 0020Accepted
0031The shaping cache is keyed on everything but colour; a glyph takes its span's colour when drawn, so fading rich text is shaped onceAccepted
0032Accessibility: a semantics tree derived from the painted frame (defaults, merge rules, modifiers), built only while assistive technology is on, sent to the hosts as diffs in one buffer; a virtual view hierarchy on Android, accessibility elements on iOS; a checker and a test APIAccepted; not tried with a screen reader
0033Radial gradients (circle or ellipse, any centre and size, any number of stops) as a quad fill, one instance per pair of neighbouring stops with half-open bands so segments never overlap; the instance grows from 144 to 160 bytes by one general vec4; Radial in the UI layer with CSS's shape, position and size keywords, stacked like a CSS background listAccepted
0034filter: blur of a box's background evaluated per pixel with no blur pass: a solid box as its own shadow (exact), a radial gradient by a 6 x 6 Gauss-Hermite quadrature of the unblurred picture (about 1% where the gradient fades out inside its box); arbitrary content not blurredAccepted
0035Inner (inset) shadows as one more quad kind, with offset, blur and spread; several shadows on one box in CSS orderAccepted
0036A radius per corner for solid and bordered rectangles; gradients, dashes and clips keep the single radiusAccepted
0037Scroll views that scroll sideways: a row that offers its children unlimited width, the same per-identity scroll state along x, and a drag given to the scroll view that runs the finger's wayAccepted
0038Live rooms: voice through LiveKit's client as a platform service that is answered once per event until a final one; one room at a time, never left connected by accident (left when the app leaves the screen, on forget_pending, when the engine goes); opt-in per app (services = ["live"] in its Cargo.toml), so that no other APK carries WebRTC; an honest refusal on iOS; the design for videoAccepted; Android host builds, never run; iOS refuses
0039What a live room carries besides sound: data messages (send_live_data, LiveEvent::Data); pictures as I420 frames kept one per video in the image store, converted on the GPU into a texture the quad pipeline samples like an image, drawn by LiveVideo, a frame scheduled only while the video is on screen; this device's camera; and its screen, shared, in which case the room goes on behind another app, held by two foreground services. Opt-in by two more names, live-video and live-screenAccepted; Android host builds, never run; iOS refuses
0040A development preview: a third host, for the Mac (tools/morningstar-preview, through winit and one new NativeSurface variant), that runs any app in a window with the mouse as a finger and the keyboard as text input, really makes its HTTP requests (the system's curl) and keeps its stored values; a supervisor that links the app through a generated runner crate, watches what the last build read, and builds and restarts on change (loading the app's library at run time rejected as unsound)Accepted; macOS only, run and scripted on one Mac, not yet used by hand
0041A new app from one command: morningstar-new in the devtools writes a complete app crate (identity, two screens, a stored value, journeys, accessibility and picture tests, an icon, and with --server a Node server skeleton) from templates kept in the binary, into apps/, and adds it to the workspace; nothing is overwrittenAccepted on the host; no generated app has run on a device
0042A live room goes on behind another app or a locked screen when the application joined it with a notice (LiveJoin::background), the app was built with live-background, and the microphone's foreground service is running; it ends by leaving, a replacement, the notification's action (Disconnected(HungUp)), the other side, a lost connection or the app being swiped away, and by nothing else. Audio routes (earpiece, loudspeaker, wired, Bluetooth) are told as LiveEvent::AudioRoutes and chosen with set_live_audio_route, through LiveKit's own audio switch. Supersedes 0038's "a room does not continue in the background"Accepted; nothing run on a device
0043Continuous integration in four jobs: format, lint and the GPU-free tests on Linux; the Android Rust code linted for arm64; the three servers' tests without keys; and every test, pixel and fidelity included, on macOS (Metal) for main only, because of its price. Toolchain pinned in the workflow, no secrets, no third-party actionsAccepted; the workflow has never run
0044The documentation site: static files under site/, built from the Markdown in docs/ by one dependency-free script; samples compiled as a crate, method tables read from doc comments, screenshots rendered by the examples, links checked at every buildAccepted
0045Released on crates.io under MIT OR Apache-2.0: twelve crates at one version, the public one morningstar-framework with its library still morningstar; the morningstar command (morningstar-cli) creates a standalone app, previews it and builds it for Android with the host carried inside, refusing a framework of another releaseAccepted; not yet published

Checklist for the owner: TalkBack on CallReady (ADR 0032)

Nothing below has been done. Build and install as usual (MORNINGSTAR_APP=callready tools/build-android.sh --install), turn TalkBack on (Settings, Accessibility, TalkBack; or hold both volume keys), and open CallReady. In adb logcat -s Morningstar the line accessibility on: frames are described should appear once, followed by accessibility: semantics update N bytes after frames that changed something and not after ones that did not.

  1. Welcome. Touching the headline says "Get job-ready with real calls, heading", once, not letter by letter. Swiping right goes through the six quotes and ends on "Let's go, button". Double-tap opens Home.
  2. Home, by swiping right from the top, in this order: "Profile, Grace, button"; "Notifications, unread, button"; "Today's practice call"; "Missing delivery, heading"; "Customer · US accent · 4 min"; "Start call, button"; "Scenarios, heading"; "Scenario settings, button"; "Angry customer, Starts a practice call, button"; "Refund request, …"; "Billing problem, …"; "Home, Tab, selected"; "Progress, Tab"; "History, Tab"; "More, Tab". The disc, the rings and the cards' numerals are never spoken.
  3. The green focus rectangle sits exactly on each control (the round call button, each card, each tab), below the status bar, not shifted or scaled. Explore by touch: sliding a finger over the screen speaks what is under it.
  4. Double-tap to activate. On "Start call": the live call opens. On a tab: the tab changes and says "selected". On "Notifications": the list opens; "Back, button" returns, and the bell then says "Notifications" without "unread".
  5. The call. After "Start call", TalkBack reads "CUSTOMER, …" (the caller's line) by itself when it changes, and "YOU · SPEAKING". The two tips are "…, Answers with this, button"; double-tapping one answers, and the caller's next line is read out without being looked for. "Mute, switch, not checked" becomes "checked", the status says "YOU · MUTED", and the tips say "disabled". "End call, button" ends it.
  6. The report. "Call report, heading"; the score as one number, "NN out of 100", not two digits; then five bars as "Clarity, 88 out of 100, progress bar" and so on; "Transcript" and "Practise again" as buttons. TalkBack's back gesture (swipe down then left) returns Home.
  7. Two-finger scroll. On a screen taller than the phone (Transcript, or Settings on a small phone), two fingers scroll it and the focus rectangle moves with the content. Swiping right past the last visible row scrolls the list by itself and continues.
  8. Editing a field. More, Profile: the name is "Grace Mushi, edit box, Your name"; double-tap brings the keyboard; typed letters are echoed; with the volume keys, moving by character and by word reads each one and moves the caret. More, Server: the same with the address.
  9. A toast. When the app shows its line under the status bar (a save that failed, or a call that fell back to the practice script because the server could not be reached), it should be spoken without being touched. This one is the least certain: it relies on TalkBack reading a live region that has just appeared.
  10. Off. Turn TalkBack off: accessibility off in the log, and no further semantics update lines while using the app.

Then the same on FundiDesk's log-in screen: "Phone number, edit box, 07XX XXX XXX"; "Password, edit box" speaking "bullet" for each character typed and never the character once it is masked; "Show password, switch"; "Log in, button".
