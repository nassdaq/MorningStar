Navigation and time

Screens

A Navigator is the stack of screens as plain application state. Nothing about it is special to the framework: a screen is a value of your own type, and view draws whichever is on top.

/// The screens there are. Plain data: a screen can carry what it shows.
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub enum Screen {
    Orders,
    Order(u32),
}

#[derive(Clone)]
pub enum Message {
    Open(u32),
    Back,
    Second,
}

pub struct Shop {
    pub screens: Navigator<Screen>,
    pub seconds: u32,
}

impl Application for Shop {
    type Message = Message;

    fn view(&self) -> Element<Message> {
        let screen = *self.screens.current();
        let content: Element<Message> = match screen {
            Screen::Orders => Button::new("Order 1042")
                .on_press(Message::Open(1042))
                .into(),
            Screen::Order(number) => col![
                Button::new("Back").plain().on_press(Message::Back),
                text(format!("Order {number}")).title(),
                text(format!("Open for {} s", self.seconds)).muted(),
            ]
            .gap(12.0)
            .into(),
        };
        // The id gives each screen its own state; the transition slides
        // screens in the direction of the last change.
        SafeArea::new(content)
            .id(screen)
            .transition(self.screens.transition())
            .into()
    }

    fn update(&mut self, message: Message) {
        match message {
            Message::Open(number) => {
                self.seconds = 0;
                self.screens.push(Screen::Order(number));
            }
            Message::Back => {
                self.screens.back();
            }
            Message::Second => self.seconds += 1,
        }
    }

    // The system's Back button or gesture. `true`: the app dealt with it.
    // `false` on the first screen leaves it to the system, which leaves
    // the app.
    fn back(&mut self) -> bool {
        self.screens.back()
    }

    // A message every second, only while an order is open. With `None`
    // the app draws nothing and wakes for nothing.
    fn tick(&self) -> Option<(Duration, Message)> {
        matches!(self.screens.current(), Screen::Order(_))
            .then_some((Duration::from_secs(1), Message::Second))
    }
}

Three things in that sample are worth copying:

  • .id(screen) on each screen's root gives every screen its own scroll positions and focus.
  • .transition(self.screens.transition()) slides screens in and out in the direction of the last change: forward for a push, backward for a pop.
  • A screen can carry data. Screen::Order(1042) is a different identity from Screen::Order(1043).

The system's Back

back() is called for the Back button and the back gesture. Return true when the app dealt with it, and false to leave it to the system, which then leaves the app. Navigator::back() returns exactly that: it pops if there is something to pop.

A screen with something of its own to close first (a sheet, a search field, a selection) checks that before the navigator. ADR 0018.

Time

tick() asks for a message after a delay. It is asked again after each one, so it repeats while it returns Some and stops when it returns None. With no timer, an idle app draws nothing and wakes for nothing.

Use it for a clock that is on screen, for polling a server while a screen is open, and for timeouts. Do not use it to animate: .animate and .transition do that without messages.
