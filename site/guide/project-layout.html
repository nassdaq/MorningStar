Project layout

Two layouts matter: an app's own directory, and the repository around it.

An app

This is what morningstar-new writes. The example apps have the same shape.

PathWhat it is
Cargo.tomlThe crate, and under [package.metadata.morningstar] the app's name, id, icon and opt-in services. They are declared here and nowhere else
src/lib.rsThe application: state, messages, view, update, effects, and the morningstar::app! line
tests/e2e.rsJourneys through the app: taps, typing and answers, with no device
tests/accessibility.rsEvery screen checked for missing labels, small touch targets and low contrast
tests/screens.rsA picture of each screen compared with its reference in tests/references/
tests/support/mod.rsThe small "device" the tests share: a frame, a finger, a keyboard
examples/screenshot.rsRenders every screen to a PNG on the development machine
assets/Fonts, the launcher icon (icon.png), images and SVG files
design/The design's reference pictures, if the app follows one
SCREENS.mdWhat every screen and control does, and what is not done
server/Only with --server: a Node server with its contract in API.md

The identity table looks like this:

[package.metadata.morningstar]
name = "Barua Talk"                  # under the launcher icon
id = "dev.morningstar.barua_talk"    # the application id
icon = "assets/icon.png"             # square PNG, 1024 is best
services = ["live", "live-video"]    # opt-in platform services

services is described in Opt-in services, the icon in Tools.

The repository

PathOwns
crates/morningstarThe public API. The only crate an app depends on
crates/morningstar-uiWidgets, state and messages, themes, effects. Apps use it as morningstar::ui
crates/morningstar-layoutThe layout engine
crates/morningstar-textFonts, shaping, the glyph atlas, vector icons, SVG
crates/morningstar-gpuThe renderer; the only crate that uses wgpu
crates/morningstar-runtimeThe engine a host drives: lifecycle in, frames out
crates/morningstar-coreShared types with no dependencies
crates/morningstar-android, crates/morningstar-iosThe Rust half of each host
templates/android, templates/iosThe native host projects. No application logic
tools/The generator, the preview, the icon and diff tools, the build scripts
examples/The framework's own demonstration apps
apps/Where morningstar-new puts a new app
docs/These pages as Markdown, and the decision records
site/These pages as a website, built from docs/
benchmarks/The benchmark method and its reports

Architecture explains how the crates depend on each other.
