Guide/Core concepts/Layout

Layout

Layout uses the words a design tool uses. A box is a column, a row or a stack. Its size on each axis is fixed, hugs its contents, or fills its parent. There is padding inside a box and a gap between its children.

Fixed, hug and fill

row![
    // Fixed: exactly 48 by 48 dp.
    Container::empty()
        .size(48.0, 48.0)
        .radius(12.0)
        .background(ThemeColor::PrimaryContainer),
    // Fill: takes the width the row has left, so this is the text
    // that wraps when the screen is narrow.
    text("Fundi wa simu, Kariakoo").fill_width(),
    // Hug (the default): as wide as its words.
    text("08:02").caption().muted(),
]
.gap(12.0)
.cross_align(CrossAlign::Center)
.fill_width()
SizeMethodMeaning
Fixed.width(dp), .height(dp), .size(w, h)Exactly this many dp
Hug.hug_width(), .hug_height()As big as the contents. The default
Fill.fill_width(), .fill_height(), .fill()The space the parent has left
Fill by weight.fill_width_weight(n), .fill_height_weight(n)A share of that space, against the other fills

.min_width, .max_width, .min_height and .max_height bound any of them, and .aspect_ratio(w / h) gives a height from a width.

Rows and columns

col![
    text("Summary").headline(),
    row![
        // Two fills share the row two to one.
        Container::new(text("Paid"))
            .padding(12.0)
            .background(ThemeColor::Surface)
            .fill_width_weight(2.0),
        Container::new(text("Due"))
            .padding(12.0)
            .background(ThemeColor::SurfaceVariant)
            .fill_width_weight(1.0),
    ]
    .gap(8.0)
    .fill_width(),
    // A spacer takes what is left, pushing the button to the bottom.
    Spacer::new(),
    Button::new("Continue").fill_width(),
]
.gap(16.0)
.padding(20.0)
.fill()

col![..] and row![..] are short for Column::new().push(..) and Row::new().push(..). Both are a Container, so both take padding, a gap, alignment and paint.

  • .gap(dp) is the space between neighbours.
  • .main_align(..) distributes children along the box's own axis; .space_between() is the common case.
  • .cross_align(..) places each child across the axis; a child overrides it with .align_self(..).
  • .center() centres on both axes.

Stacks

A stack lays its children on top of each other, the later over the earlier. A child is pinned with .place(..) to one of nine anchors and nudged with .offset(x, y).

stack![
    Container::empty()
        .size(56.0, 56.0)
        .radius(16.0)
        .background(ThemeColor::SurfaceVariant),
    // Pinned to one of nine anchors, then nudged outwards.
    Container::new(text("3").caption().color(ThemeColor::OnPrimary))
        .padding_xy(6.0, 2.0)
        .radius(999.0)
        .background(ThemeColor::Primary)
        .place(Alignment::TOP_RIGHT)
        .offset(6.0, -6.0),
]

Rows that wrap

A row wraps only if told to. Then a child that does not fit starts the next line, and the row is as tall as its lines.

let mut chips = Wrap::new().gap(8.0).line_gap(8.0).fill_width();
for tag in tags {
    chips = chips.push(
        Container::new(text(*tag).label())
            .padding_xy(12.0, 6.0)
            .radius(999.0)
            .border(1.0, ThemeColor::Divider),
    );
}

Scrolling

let mut list = Column::new().gap(12.0).padding(20.0).fill_width();
for (index, row) in rows.into_iter().enumerate() {
    // An id per row keeps a finger's press with its row when rows
    // are added or removed above it.
    list = list.push(text(row).fill_width().id(("row", index)));
}
// The id keeps this screen's scroll position its own.
SafeArea::new(ScrollView::new(list).id("orders-scroll"))
    .id("orders")

A ScrollView fills its parent, so it needs a height from above. Its position belongs to the widget's identity: while a scroll view with the same id is in consecutive frames, its position is kept. ScrollView::horizontal(..) scrolls sideways. To move one from code, see ScrollTo.

The safe area and the keyboard

SafeArea::new(child) insets its child by the status bar, the gesture bar and any display cutout. Container::safe_area(edges) does the same for chosen edges, for a bar that should reach the screen's edge with its contents kept clear.

While the keyboard is up, boxes that pad for the bottom safe area pad for the keyboard instead, and the focused field is scrolled into view.

A layout that depends on the screen

Implement view_in instead of view to be told what you are drawn on. The Viewport gives the size, the insets and the keyboard's height in dp, and measures text exactly as layout will.

fn view_in(&self, viewport: &Viewport<'_>) -> Element<()> {
    // Side by side on a wide screen, one under the other on a
    // narrow one. Widths are in dp, like everything else.
    let cards = if viewport.width() >= 600.0 {
        Row::new()
    } else {
        Column::new()
    };
    cards
        .gap(16.0)
        .push(text("Today"))
        .push(text("This week"))
        .into()
}

Rules worth knowing

  • Sizes hug by default. A box is as big as its children; a text as big as its words.
  • Fill inside hug collapses. A fill_width() child of a box that hugs its width gets no width. Give the parent a width.
  • In a row, the text that should wrap must fill_width(). Two long hugging texts in one row overflow.
  • Children start at the top-left unless the parent says otherwise.
  • There is no right-to-left mode. Start is left.

Ui::overflows() lists boxes whose children do not fit; the example apps' tests assert that it is empty.

The engine's design is ADR 0010; wrapping, the viewport and scrolling from code are ADR 0021.
