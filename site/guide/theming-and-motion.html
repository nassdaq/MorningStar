Themes and motion

The theme

A theme is plain data: colour roles, a type scale, spacing, radii and font families. Start from Theme::LIGHT or Theme::DARK and change what the design changes.

/// The dark theme with the brand's colours.
const THEME: Theme = Theme {
    colors: Colors {
        background: hex(0x0B0B0C),
        surface: hex(0x121214),
        primary: hex(0xE3AE3A),
        on_primary: hex(0x141005),
        ..Theme::DARK.colors
    },
    ..Theme::DARK
};

pub struct Branded {
    pub onboarding: bool,
}

impl Application for Branded {
    type Message = ();

    fn theme(&self) -> Theme {
        THEME
    }

    fn view(&self) -> Element<()> {
        // Colours are named, not copied: the same view follows whatever
        // theme the application returns.
        Container::new(text("Morningstar").title().color(ThemeColor::Primary))
            .background(ThemeColor::Background)
            .center()
            .fill()
            .into()
    }

    fn update(&mut self, _message: ()) {}

    // The status and navigation bars' icons follow the theme by
    // themselves. A screen whose edges are not the theme's background
    // says what is behind them: here, a light picture under onboarding.
    fn system_bars(&self) -> Option<SystemBars> {
        self.onboarding.then_some(SystemBars::DARK_CONTENT)
    }
}

Widgets take a colour either as a value (hex(0x2F6BFF)) or as a role (ThemeColor::Primary). Roles follow whatever theme theme() returns, so one view can serve a light and a dark theme.

VariantMeaning
BackgroundThe screen background.
SurfaceCards, sheets, bars: surfaces that sit on the background.
SurfaceVariantA quieter surface: input fields, chips, secondary buttons.
PrimaryThe brand or accent colour.
OnPrimaryText and icons drawn on Primary.
PrimaryContainerA tint of the primary colour for soft highlights.
TextMain text.
TextMutedSecondary text: captions, hints, metadata.
DividerHairlines and outlines.

The fields of each part are in the Theme reference.

The system's bars

The screen is drawn edge to edge, under the status bar and the navigation bar. Their icons are dark over a light theme and light over a dark one without the app saying anything. system_bars() overrides that for a screen whose edges are not the theme's background, as in the sample above. ADR 0026.

This has been tested on the development machine only; the bars' colours have not yet been checked on a phone.

Motion

view always describes the screen as it should be. A widget shows a change gradually only if it asks to.

fn view(&self) -> Element<Message> {
    let mut lines = Column::new().gap(8.0).fill_width();
    for line in &self.lines {
        lines = lines.push(text(line.clone()).fill_width());
    }
    col![
        // The view only says how tall the panel is now; `animate`
        // shows the change happening.
        Container::empty()
            .height(if self.open { 160.0 } else { 56.0 })
            .fill_width()
            .radius(16.0)
            .background(ThemeColor::Surface)
            .animate(Duration::from_millis(200), Easing::EaseOut)
            .on_press(Message::Toggle),
    ]
    // Present only while open: fades in when it enters the tree and
    // out when it leaves.
    .push_maybe(self.open.then(|| {
        Container::new(text("Details"))
            .id("details")
            .transition(Transition::fade())
    }))
    .push(ScrollView::new(lines).id("chat"))
    .gap(12.0)
    .fill()
    .into()
}
You wantUse
A change of opacity, transform, offset, solid background or fixed size to be seen happening.animate(duration, easing) on the widget
A widget to fade, slide or scale in when it appears and out when it goes.transition(Transition::fade()), ::slide(x, y), ::scale(from)
Screens to slide in the direction of the navigation.transition(navigator.transition()) on each screen's root
A scroll that glidesScrollTo::..().animated()

Easing is Linear, EaseIn, EaseOut (the default) or EaseInOut.

Frames are produced only while something is on its way. When the last animation ends, the app is as idle as it was.

Reduce motion

When the user has asked the system for less motion, every animation, transition and gliding scroll takes no time. The app does nothing for this. In a test, Ui::set_reduce_motion(true) does the same.
