Effects and services

An application never does I/O itself. Work that takes time is asked for from effects as data, the host carries it out with the platform's own stack, and the result comes back as a message. This is what lets a test drive a whole app with no device: the test answers in the host's place.

The pattern

update decides what should start and records it. effects, which is called after every update, queues the requests. Each request names the message its answer becomes.

#[derive(Clone, Debug)]
pub enum Message {
    Refresh,
    Loaded(Result<HttpResponse, HttpError>),
    Copy,
}

/// Work `update` has decided on and `effects` has not started yet.
enum Start {
    Fetch,
    Remember(String),
    Copy(String),
}

#[derive(Default)]
pub struct Orders {
    start: Vec<Start>,
    pub loading: bool,
    pub status: String,
    pub install_id: String,
}
// `update` returns at once: it records what should be started.
fn update(&mut self, message: Message) {
    match message {
        Message::Refresh => {
            self.loading = true;
            self.start.push(Start::Fetch);
        }
        Message::Loaded(result) => {
            self.loading = false;
            self.status = match result {
                Ok(response) if response.is_success() => {
                    let body = response.text().unwrap_or_default().to_owned();
                    self.start.push(Start::Remember(body.clone()));
                    body
                }
                Ok(response) => format!("The server answered {}.", response.status),
                Err(HttpError::Offline) => "No connection.".to_owned(),
                Err(error) => format!("No answer: {error}."),
            };
        }
        Message::Copy => self.start.push(Start::Copy(self.status.clone())),
    }
}

// Called after every `update`: requests leave as data, and each
// answer comes back as a message.
fn effects(&mut self, out: &mut Effects<Message>) {
    for start in self.start.drain(..) {
        match start {
            Start::Fetch => out.http(
                HttpRequest::get(format!("{SERVER}/v1/orders/latest"))
                    .header("X-Device-Id", self.install_id.clone())
                    .timeout(Duration::from_secs(10)),
                Message::Loaded,
            ),
            // Kept on the phone; there at the next `setup`.
            Start::Remember(order) => out.store(LAST_ORDER, order),
            Start::Copy(text) => out.set_clipboard(text),
        }
    }
}

HTTP

A request is built from a method and a URL, with headers, a body and a timeout. The response has a status, headers and a body, read as text with response.text().

  • Requests run on the platform's own HTTP stack with the platform's certificates.
  • Plain http:// is refused by the hosts except to the development machine: localhost, 127.0.0.1 and 10.0.2.2.
  • A response larger than 10 MB is an error.
VariantMeaning
OfflineThe server could not be reached: no network, the name did not resolve, or the connection was refused or dropped.
TimeoutThe exchange took longer than the request's timeout.
InvalidUrlThe URL is not an absolute http or https URL.
TooLargeThe response body is larger than MAX_HTTP_RESPONSE_BYTES.
UnsupportedNothing can make requests here: there is no host (a test without a driver, a screenshot tool) or the host is older than this library.
FailedAnything else, described by the platform: a TLS failure, a cleartext request the platform's policy forbids.

There is no JSON library in the framework. The examples read the few fields they need with a small reader of their own (src/json.rs in a generated app).

Values kept on the phone

out.store(key, value) keeps a string under a key in the app's private storage. Stored values are handed to setup before the first frame, with no request and no waiting, which is the usual way to read them:

fn setup(&mut self, setup: &mut Setup<'_>) {
    // Known before the first frame, with no request and no waiting:
    // this installation's id, and the values stored on earlier runs.
    self.install_id = setup.install_id().to_owned();
    self.status = match setup.stored(LAST_ORDER) {
        Some(order) => format!("Last time: {order}"),
        None => "Nothing yet.".to_owned(),
    };
}

setup.install_id() is an id made once per installation. The examples send it to their servers as X-Device-Id to tell one phone from another without an account.

Recording and playback

start_recording asks for the microphone the first time and answers when it is running, or with AudioError::PermissionDenied. A recording stops by itself after 60 seconds and when the app leaves the screen. stop_recording hands over what was recorded as a Recording, which becomes an AudioClip to send to a server or play back.

VariantMeaning
PermissionDeniedThe user has not allowed the microphone.
BusyA recording is already running (for "start"), or the microphone or the audio output is held by something that would not give it up.
UnsupportedNothing can record or play here: there is no host (a test without a driver, a screenshot tool), the host is older than this library, or the device has no microphone.
NotRecording"Stop recording" with no recording to stop.
InterruptedPlayback ended before the clip did: the application stopped it, started another clip, went to the background, or lost the audio output to a phone call.
FailedAnything else, described by the platform.

Where services work

ServiceAndroidiOSPreview on a MacA test
HTTP, storage, clipboardYesWritten, never compiledYesAnswered by the test
Recording and playbackYesWritten, never compiledAnswers UnsupportedAnswered by the test
Live roomsYes, for apps that opt inAnswers UnsupportedAnswers UnsupportedEvents sent by the test

"Yes" for Android means the code is there and the app builds with it. What has actually been observed on a phone is in Platform status. Where nothing can do the work at all (a screenshot program, Ui::new in a test) every request answers Unsupported at once, so an app never waits for ever.

The design is ADR 0019.
