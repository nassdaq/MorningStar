LiveVideo

The picture of a camera or a shared screen from a live room.

fn view(&self) -> Element<Message> {
    let picture: Element<Message> = match self.picture {
        // Frames never pass through the application: it draws the
        // track, and the host fills it in.
        Some(track) => LiveVideo::new(track).fit(ImageFit::Cover).fill().into(),
        None => Container::empty()
            .background(ThemeColor::Surface)
            .fill()
            .into(),
    };
    stack![
        picture,
        col![
            text(self.status.clone()).color(ThemeColor::OnPrimary),
            Button::new(if self.muted { "Unmute" } else { "Mute" })
                .secondary()
                .on_press(Message::Mute(!self.muted)),
            Button::new("Hang up")
                .destructive()
                .on_press(Message::HangUp),
        ]
        .gap(12.0)
        .padding(20.0)
        .place(Alignment::BOTTOM_CENTER),
    ]
    .fill()
    .into()
}
MethodWhat it does
new(track: VideoTrack)The video drawn by track.
fit(fit: ImageFit)How the picture fills a box of a different shape.
radius(dp: f32)Corner radius in dp.
tint(color: impl Into<ColorRef>)Multiplies every pixel by a colour: white with an alpha of 0.5 shows the picture half transparent.
  • The app draws a track, which it gets from LiveEvent::VideoStarted. The frames never pass through the application.
  • It draws nothing until a frame exists, so whatever is stacked underneath is the placeholder.
  • A frame is requested only while a LiveVideo for that track is on screen and a new picture has arrived.
  • For a camera, ImageFit::Cover fills the box; for a shared screen, ImageFit::Contain shows it whole.

Pictures need the live-video service in the app's Cargo.toml; see Opt-in services. In a test or a screenshot, frames are supplied with Frame::set_video_frame or the devtools' screenshot_frame_with_videos.

Not yet seen on a phone. The conversion and the widget pass their tests on the development machine. ADR 0039.
