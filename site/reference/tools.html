morningstar-new

cargo run -q -p morningstar-devtools --bin morningstar-new -- my-app --name "My App" --id com.example.myapp
Creates a new Morningstar application in this workspace: a crate that builds,
passes its own tests and can be installed on a phone as it is.

Usage: morningstar-new <package> [options]

  <package>              the Cargo package and the app's directory: lower-case
                         letters, digits and hyphens, like my-app

Options:
  --name <text>          the name under the launcher icon
                         (default: the package in words, "My App")
  --id <id>              the application id, like com.example.myapp
                         (default: dev.morningstar.<package>; choose your own
                         before the app is given to anyone)
  --services <list>      opt-in platform services, separated by commas:
                         live (voice rooms) and its parts: live-video,
                         live-screen, live-background
                         (default: none; each adds to what the app carries)
  --server               also write a Node server skeleton in server/, and make
                         the app talk to it
  --port <number>        the port that server listens on (default: 8790)
  --dir <directory>      where the app's directory is made, relative to the
                         workspace root (default: apps)
  --workspace <dir>      the workspace root, if not this directory or one above
  -h, --help             print this help

What is written: Cargo.toml (name, id, icon and services, declared once),
src/lib.rs (two screens, navigation, a stored value), tests (journeys,
accessibility, pictures of the screens), examples/screenshot.rs, a launcher
icon, fonts, README.md, SCREENS.md and design/README.md; and the app is added
to the workspace's members. Nothing is overwritten.

Exit status: 0 created, 2 usage error or nothing written.

Your first app walks through what it writes. New apps go under apps/; the reason is in ADR 0041.

The live preview

tools/preview.sh my-app

A development host for a Mac. It drives the same engine the phone hosts drive, in a phone-shaped window, with the mouse as a finger and the keyboard for text fields.

Runs a Morningstar app in a window on this Mac and reloads it when its source changes.

  morningstar-preview <app> [options]        (tools/preview.sh <app> [options])

<app> is the Cargo package of the app, such as barua-talk.

Options:
  --size <W>x<H>            the screen in dp (default 390x844)
  --scale <S>               physical pixels per dp (default: this display's,
                            less if the window would not fit on it)
  --insets <T>[,<B>]        the safe area's top and bottom insets in dp, or
                            <L>,<T>,<R>,<B> (default 51,21: a status bar and a
                            gesture bar; 0 for none)
  --keyboard <H>            imitate a soft keyboard this many dp high while a
                            text field has the focus (default 0: none)
  --position <X>,<Y>        the window's top-left corner in screen points, for
                            the first start (default: where it last was)
  --reduce-motion           start with the system's "reduce motion" on
  --fresh                   forget the stored values first: a first launch
  --no-watch                build and run once; do not reload
  --screenshot-after <MS> <PATH>
                            save the screen as a PNG after MS milliseconds and
                            quit (implies --no-watch)
  --tap <X>,<Y>             tap at this point in dp by itself; with --type <TEXT>
  --type <TEXT>             (into the focused field), --back and --wait <MS>,
  --back, --wait <MS>       a script: steps run in the order given, half a
                            second apart, starting when the app has drawn
  --manifest-path <PATH>    the app's Cargo.toml, if it is not in or under the
                            current directory's workspace
  --help                    this text

Keys, in the window:
  the mouse is a finger; the wheel or two fingers on the trackpad scroll
  typing goes to the focused text field; Cmd+A/C/X/V/Z and the arrows work
  Esc            the system's back (with a field focused: put the keyboard away)
  Cmd+S or F2    save the screen as a PNG under target/preview/<app>/
  Cmd+R or F5    start the app again; with Shift, as on its first launch
  F3             turn "reduce motion" on and off
  F4             turn the safe-area insets on and off
  F1             print this list
KeyDoes
Typing, arrows, Cmd+A/C/X/V/ZGo to the focused field
EscThe system's Back, or "keyboard away" while a field is focused
Cmd+S or F2Save a screenshot
Cmd+R or F5Restart the app; with Shift, restart with stored values forgotten
F3Toggle reduce motion
F4Toggle the insets
F1List the keys

What to know about it:

  • Reload is rebuild and restart. On a source change the app is rebuilt and its process replaced. The old window stays up during a build and after a failed one, with the errors in the terminal. Nothing in memory survives; what the app stored does.
  • HTTP, stored values and the clipboard really work, so an app talks to its server on the same machine. Recording, playback and live rooms answer Unsupported.
  • It is not a phone. It is a debug build with one finger, no real soft keyboard and no system bars. Plain http:// is not refused as it is on a phone. Frame times in it mean nothing.
  • macOS only.

The scripted flags (--tap, --type, --back, --screenshot-after) are how it was tested: nobody has yet clicked or typed in the window by hand. ADR 0040.

Screenshots

Every app has a small program that renders its screens through the real renderer on the development machine's GPU.

cargo run -p my-app --example screenshot -- out/
cargo run -p fundidesk --example screenshot -- out/ 07 --diff --phone

The designed examples take screen names, and options to compare with the design (--diff), to render in a phone's frame (--phone, --small, --tall), to render other states (--states, --online) and to print the semantics tree (--semantics). The header of each examples/screenshot.rs lists what that app's program takes.

morningstar-diff

cargo run -q -p morningstar-devtools --bin morningstar-diff -- design.png out/home.png --out heat.png
Compares a candidate image (a screenshot) with a reference (a design).

Usage: morningstar-diff <reference.png> <candidate.png> [options]

The reference is resampled to the candidate's size; all coordinates in the
report and in the options are candidate pixels, from the top-left corner.

Options:
  --out <file>             write a heat map PNG (candidate in grey, differences
                           yellow to red, listed regions outlined and numbered)
  --side-by-side <file>    write reference | candidate | heat map as one PNG
  --threshold <error>      smallest colour error that counts as a difference;
                           0 identical, 2 just visible, 100 black vs white
                           [default: 2]
  --aa-radius <pixels>     accept edges that moved by up to this many pixels or
                           are anti-aliased differently; 0 is strict [default: 1]
  --max-diff <percent>     pass when at most this percentage of the compared
                           pixels differ [default: 0.1]
  --ignore <x,y,w,h>       leave a rectangle out of the comparison; repeatable
  --fit <width|stretch>    on an aspect-ratio mismatch: scale the reference to
                           the candidate's width and align the tops, or distort
                           it to cover the candidate [default: width]
  --allow-aspect-mismatch  do not fail just because the aspect ratios differ
  --max-regions <count>    how many regions to list [default: 10]
  --json                   print the report as JSON instead of text
  -h, --help               print this help

Exit status: 0 the images match, 1 they differ, 2 usage or file error.

Design to code explains how to read its report.

morningstar-svg

cargo run -q -p morningstar-devtools --bin morningstar-svg -- art.svg out/art.png --scale 3
Renders an SVG file to a PNG as a Morningstar app would draw it.

Usage: morningstar-svg <file.svg> <out.png> [options]

Options:
  --size <W>[x<H>]       the image's size in pixels; one number is a square. The
                         picture is fitted and centred, as in an app
  --scale <S>            pixels per unit of the file's own size (default 1; a
                         phone is 2 to 3). Ignored with --size
  --background <B>       what is behind the picture: none (default; the PNG is
                         transparent), checker, or a colour as #RRGGBB
  --color <#RRGGBB>      the colour of `currentColor` (default black)
  --lenient              leave out what the loader does not support instead of
                         refusing the file, and list it. For a first look only:
                         an app should load a file that needs no leniency
  -h, --help             print this help

Prints the file's size, whether it is single-ink (an icon that takes any colour
from one mask, see Icon::svg), and what was written.
Exit status: 0 done, 1 the file is outside the supported subset (the message
says what and where: file:line:column), 2 usage or file error.

morningstar-icon

cargo run -q -p morningstar-devtools --bin morningstar-icon -- my-app --preview out/icon.png
Generates an app's launcher icons, and prints its name and ids, from the
[package.metadata.morningstar] table of its Cargo.toml:

    [package.metadata.morningstar]
    name = "CallReady"                # under the icon (default: the package name)
    id = "dev.morningstar.callready"  # application id (default: dev.morningstar.<lib>)
    icon = "assets/icon.png"          # square PNG, 512 or more, best 1024, full-bleed
                                      # (default: this path if the file exists,
                                      # otherwise the built-in Morningstar icon)
    icon_foreground = "assets/icon-foreground.png"
                                      # optional Android adaptive foreground: square,
                                      # transparent, content in the middle 61%
    icon_background = "#0E0E0E"       # optional colour behind the foreground
                                      # (default: the icon's top-left pixel)

Usage: morningstar-icon <package> [options]

Options:
  --android <dir>        write an Android resource directory: mipmap-*/ic_launcher
                         (.png, _round.png, _foreground.png), the adaptive icon in
                         mipmap-anydpi-v26 and its colour in values
  --ios <dir>            write Assets.xcassets (AppIcon: one 1024x1024 opaque PNG)
                         and Morningstar.xcconfig (bundle id and names) for the iOS
                         host. Not verified with Xcode.
  --preview <file.png>   write one picture of the icon in every form: square,
                         round, and adaptive under a circle and a squircle, at
                         192, 96 and 48 pixels
  --print <what>         print one value and a newline: name, id (Android
                         application id), bundle-id (iOS), lib (the Rust
                         library's name), icon (the source picture, or
                         `built-in`) or services (the opt-in platform
                         services the app declares, separated by commas;
                         an empty line for none)
  --manifest-path <file> a Cargo.toml of the workspace, if not the current
                         directory's
  -h, --help             print this help

Files whose content would not change are left untouched.
Exit status: 0 done, 2 usage error or a problem with the manifest or icon.

The build scripts call it; you run it yourself to look at an icon in every form before shipping it. ADR 0020.

tools/adb-guarded.sh

tools/adb-guarded.sh check
tools/adb-guarded.sh tap 540 1200
tools/adb-guarded.sh screencap out.png

A phone connected over adb belongs to a person who may be using it. This script is the only way anything in the repository may send input to a phone or capture its screen. Before every single action it checks that the expected app (MORNINGSTAR_GUARD_PACKAGE) is in front, and refuses otherwise with exit status 3. Use it only when the phone's owner has agreed and is not using the app; prefer proving behaviour from adb logcat -s Morningstar.

The documentation

python3 tools/build-docs.py            # docs/ -> site/
python3 tools/build-docs.py --check    # fail if site/ is out of date or a link is broken
tools/docs-screenshots.sh              # re-render every screenshot and tool help text

The pages are Markdown under docs/, listed in docs/site.json. The code samples are regions of examples/docs-snippets, which is compiled and linted with the workspace, and the method tables are read from the source's doc comments. The builder needs only Python 3. ADR 0044.

Benchmarks

cargo run --release -p morningstar-bench -- --markdown

Measures what building and drawing each example screen costs on the development machine. benchmarks/android/measure.sh is the method for a phone. See Performance.
