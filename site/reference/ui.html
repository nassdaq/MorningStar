Ui and testing

Ui runs an Application. In an app it appears once, in morningstar::app!(Ui::new(..)). In a test it is the handle on everything: the app's state, the requests it made, the layout of the last frame, and the semantics tree. Testing is the guide.

Creating one

MethodWhat it does
new(app: A)Wraps an application.
testing(app: A)Wraps an application for a test, with nothing behind it: every request it makes of the platform (Application::effects) is held until the test answers it.
with_services(app: A, fake: impl FnMut(&ServiceRequest) -> Option<ServiceResult> + Send + 'static)As testing, with a stand-in for the host

Ui::new answers every request with Unsupported when no host is attached. Ui::testing holds requests for the test to answer.

The application

MethodWhat it does
app() -> &AThe application state.
app_mut() -> &mut AThe application state, mutably.
send(message: A::Message)Delivers a message as if a widget had been tapped.
back() -> boolDelivers the system back gesture or key to the application (Application::back) and returns its answer.

Answering effects

MethodWhat it does
pending_effects() -> &[ServiceCall]The requests the application has made that are waiting for the test to answer them, oldest first.
effects_in_flight() -> usizeHow many requests the application is still waiting for an answer to, whoever is carrying them out.
resolve(id: ServiceId, result: ServiceResult) -> boolAnswers the request with this id: the application gets its message at once.
answer_http(result: Result<HttpResponse, HttpError>) -> boolAnswers the oldest pending HTTP request: "the server replies this".
answer_recording_started(result: Result<(), AudioError>) -> boolAnswers the oldest pending start_recording.
answer_recording(result: Result<Recording, AudioError>) -> boolAnswers the oldest pending stop_recording: "the recording is these bytes".
answer_playback(result: Result<(), AudioError>) -> boolAnswers the oldest pending play: the clip finished, or failed.
deliver_effects() -> usizeDelivers every answer that is known and has not reached the application yet, and those that become known as a result, until none is left: what a load read, what the stand-in host of with_services answered, and, when there is neither a host nor a test driver, the Unsupported failure of each request.
stored(key: &str) -> Option<&str>The value the application has stored under key, in the memory of the test driver.
set_stored(key: impl Into<String>, value: impl Into<String>) -> boolPuts a value into the test driver's memory, for the application to load.

Live rooms

MethodWhat it does
live_room() -> Option<&LiveRoom>The live room the application has joined, under the test driver: what it joined with (the address and the ticket it used), and whether its microphone and loudspeaker are on now.
live_event(event: LiveEvent) -> boolSomething happens in the live room the application has joined: "the room connected", "Baraka came in", "the connection was lost".
live_app_hidden() -> boolThe app leaves the screen, as far as the live room is concerned: the driver does what a host that can keep a room in the background does (ADR 0042).
live_hang_up_from_notice() -> boolThe user ends the room from its notification while the app is in the background: the room is over (LiveDisconnect::HungUp) and the application is told at once.

Layout and scrolling

MethodWhat it does
rect_of(id: impl Hash) -> Option<Rect>Where the widget with this explicit .id(..) was laid out in the last frame, in physical pixels, or None if it was not in that frame's tree.
visible_rect_of(id: impl Hash) -> Option<Rect>The part of the widget with this explicit .id(..) that the last frame showed
scroll_to(to: ScrollTo)Asks for a scroll as Effects::scroll does; carried out in the next frame.
set_reduce_motion(reduce: bool)Tells the layer that the user has asked the system for less motion (Android's "remove animations", iOS's "reduce motion").
is_animating() -> boolTrue if something was still animating in the last frame (an animated change, a transition, or a widget leaving).
scroll_offset(id: impl Hash) -> Option<f32>The scroll position, in dp, of the scroll view with this explicit .id(..)
max_scroll_offset(id: impl Hash) -> Option<f32>The furthest the scroll view with this .id(..) can scroll, in dp.
overflows() -> Vec<Overflow>Boxes of the last frame whose children do not fit inside them, in dp.

Focus, selection and the clipboard

MethodWhat it does
has_focus() -> boolTrue while a TextInput has focus (and so the keyboard is asked for).
is_focused(id: impl Hash) -> boolTrue if the TextInput with this explicit .id(..) has focus.
caret() -> Option<usize>Where the caret of the focused input is, as a byte offset into its value.
composing() -> Option<(usize, usize)>The part of the focused input's value the keyboard is still composing (shown underlined), as byte offsets.
selection() -> Option<(usize, usize)>The selected part of the focused input's value, as byte offsets (start before end); None if no input has focus or nothing is selected.
select(id: impl Hash, range: std::ops::Range<usize>) -> boolGives the focus to the TextInput with this explicit .id(..) and selects bytes range of its value (moved back to character boundaries; an empty range only places the caret, at its start).
selection_menu_shown() -> boolTrue while the contextual menu (Cut, Copy, Paste, Select all) is shown over the focused input.
selection_handles() -> [Option<Rect>; 2]Where the last frame put the two handles of the selection, the start's first, as the rectangles (px) a touch takes hold of them in; None for a handle that is not shown (nothing selected, the selection was made by key, or that end is scrolled out of sight).
selection_menu() -> Vec<(&'static str, Rect)>The items of the contextual menu the last frame drew, left to right: each label and its rectangle (px).
clipboard() -> Option<&str>The text on the clipboard of a Ui that has no platform behind it (testing, with_services, or no host at all): what a field last copied or cut, or what set_clipboard put there.
set_clipboard(text: impl Into<String>)Puts text on the stand-in clipboard, as if the user had copied it in another application; see clipboard.
clear_focus()Takes the focus away from whichever input has it; the keyboard goes away with the next frame.

Accessibility

MethodWhat it does
set_accessibility(on: bool)Has every frame from now on described for assistive technology (semantics), whatever the host says.
semantics() -> &SemanticsTreeThe last frame as a screen reader finds it: the nodes it can land on, in reading order, with their roles, labels, values, states and actions (the crate documentation, "Accessibility", has the rules).
accessibility_issues() -> Vec<AccessibilityIssue>What is wrong with the last frame for someone who uses a screen reader, sees poorly or aims poorly; empty when nothing is.
announcements() -> &[String]What the application has asked a screen reader to say (Effects::announce) so far, oldest first.
perform(id: u64, action: Action) -> boolDoes to the node with identity id of semantics what assistive technology would: the same code runs for a TalkBack double tap.
activate(label: &str) -> boolperforms Action::Activate on the first node that can be activated and whose label is exactly label: "double tap on the thing called ..".
